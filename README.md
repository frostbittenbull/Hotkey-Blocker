# Hotkey Blocker

Тёмное WinAPI-приложение на чистом C++ (без сторонних фреймворков) со следующими функциями:

- **Блокировка сочетаний клавиш.** Через `WH_KEYBOARD_LL` перехватывает и глотает
  любые заданные комбинации (например, Ctrl+Esc) до того, как они дойдут до
  Explorer/системы. Комбинации добавляются кнопкой «Добавить» — нажимаете нужное
  сочетание, оно само определяется и сохраняется.
- **Единственный экземпляр.** Повторный запуск .exe не плодит процессы, а
  разворачивает уже запущенное окно (через `CreateMutex` + широковещательное
  оконное сообщение `RegisterWindowMessage`).
- **Иконка в трее — опционально.** По умолчанию выключена (галочка в
  настройках); при закрытии окна (крестик) процесс не завершается, а просто
  прячет окно — вернуть его можно повторным запуском .exe или через трей, если
  иконка включена.
- **RBTray-логика.** При включённой галочке правый клик по кнопке «свернуть»
  ЛЮБОГО окна в системе сворачивает это окно в отдельную иконку в трее
  (как в оригинальной утилите RBTray), а не просто на панель задач.
- **Защита от сна/выключения экрана.** Чекбокс запускает фоновый поток,
  который каждые 30 секунд вызывает `SetThreadExecutionState` — это прямой
  нативный аналог присланного вами PowerShell-скрипта, без запуска
  powershell.exe в фоне.
- **Тёмная тема:** тёмный заголовок окна (`DwmSetWindowAttribute`,
  `DWMWA_USE_IMMERSIVE_DARK_MODE`), тёмный фон, owner-draw кнопки и список.
- **Скруглённые углы** — у самого окна (нативно через DWM,
  `DWMWA_WINDOW_CORNER_PREFERENCE`), у кнопок и у боксов чекбоксов
  (кастомная отрисовка `RoundRect`).
- **Анимации** — плавная подсветка кнопок/чекбоксов при наведении мыши,
  анимированная «дорисовка» галочки при включении чекбокса, мягкое
  появление окна (fade-in) при разворачивании из трея или запуске.
- **Иконка** приложения — своя, встроена в exe (`icon.ico`), используется и
  для окна, и для трея.
- **Автозапуск сразу в трее** — при запуске через автозагрузку Windows окно
  не разворачивается, программа сразу уходит в фон/трей (реализовано через
  скрытый аргумент командной строки `--minimized`, который сама программа
  дописывает в реестр).
- **Контекстное меню трея** — помимо «Открыть»/«Выход» содержит те же 5
  переключаемых пунктов, что и в окне настроек (значок в трее, не спать,
  RBTray, автозагрузка, прозрачность) — можно менять их прямо из трея, не
  открывая окно.
- **Горячие клавиши прозрачности окна** — чекбокс включает глобальные
  сочетания `Ctrl+Shift+0`…`Ctrl+Shift+9` (обычный цифровой ряд над буквами,
  не numpad): `Ctrl+Shift+1`…`Ctrl+Shift+9` ставят активному окну
  непрозрачность 10%…90%, `Ctrl+Shift+0` возвращает 100% (полностью
  непрозрачно).

Настройки хранятся в `%APPDATA%\HotkeyBlocker\config.ini`.

## Структура проекта

```
HotkeyBlocker/
├── src/
│   ├── main.cpp         — весь код приложения
│   ├── app.rc            — ресурсный скрипт (подключает манифест)
│   └── app.manifest       — манифест (DPI-awareness, common controls v6)
├── .vscode/
│   ├── tasks.json         — задача сборки для VSCode (Ctrl+Shift+B)
│   └── c_cpp_properties.json
├── build.bat              — сборка одной командой из cmd
└── HotkeyBlocker.exe       — уже собранный exe (готов к запуску)
```

## Сборка в VSCode (Windows)

1. Установите **MinGW-w64**, проще всего через [MSYS2](https://www.msys2.org/):
   ```
   pacman -S mingw-w64-x86_64-gcc
   ```
   и добавьте `C:\msys64\mingw64\bin` в переменную `PATH`.
   (Подойдёт и любой другой дистрибутив MinGW-w64 — главное, чтобы `g++` и
   `windres` были доступны из терминала.)
2. Откройте папку `HotkeyBlocker` в VSCode, поставьте расширение **C/C++**
   (ms-vscode.cpptools).
3. При необходимости поправьте `compilerPath` в
   `.vscode/c_cpp_properties.json` под свой путь к `g++.exe` — это влияет
   только на подсветку/автодополнение, не на сборку.
4. Нажмите **Ctrl+Shift+B** (Run Build Task) — соберётся `HotkeyBlocker.exe`
   в корне проекта.

Либо без VSCode — просто запустите `build.bat` из папки проекта (в командной
строке, где доступен `g++`).

## Уже собранный exe

В релизе также лежит **готовый `HotkeyBlocker.exe`**, собранный кросс-компилятором
MinGW-w64 (статически слинкован — не требует установки рантайма). Можно сразу
запускать и проверять поведение, а исходники при этом открыты в VSCode для
доработки.

## Как пользоваться

1. Запустите `HotkeyBlocker.exe` — откроется тёмное окно настроек.
2. Нажмите «Добавить», затем нажмите нужную комбинацию (например Ctrl+Esc) —
   она появится в списке и сразу начнёт блокироваться.
3. Отметьте нужные чекбоксы («трей», «не спать», «RBTray»).
4. Закройте окно крестиком — программа продолжит работать в фоне (без иконки
   в трее, если она не включена). Чтобы снова открыть настройки — запустите
   `HotkeyBlocker.exe` ещё раз (новый процесс не создастся, откроется старое
   окно), либо кликните по иконке в трее, если она включена.
5. Чтобы полностью закрыть программу — включите иконку в трее и выберите
   «Выход» в контекстном меню (без включённого трея штатного способа выйти
   через UI нет; для полной остановки процесса используйте Диспетчер задач
   или временно включите чекбокс трея).

## Технические детали / что можно доработать

- Список блокируемых комбинаций и настройки хранятся построчно в
  `config.ini` — формат простой текстовый, легко расширить.
- RBTray-детект основан на `WM_NCHITTEST` → `HTMINBUTTON`, что работает для
  стандартных (не кастомных) заголовков окон; окна с полностью самодельным
  non-client rendering (некоторые Electron/Chromium-приложения) могут не
  поддержать это без дополнительных костылей.
- Если нужен полноценный пункт «Выход» прямо в главном окне (без трея) —
  можно добавить отдельную кнопку в UI, которая вызывает `DestroyWindow`
  напрямую (сейчас единственный «чистый» выход через трей сделан намеренно,
  по аналогии с описанным вами сценарием «висит и не мешает»).
